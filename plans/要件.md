# オフライン地図 PWA 仕様書

## 1. 概要

国土地理院が提供する地理院タイルを利用し、オンライン・オフラインの双方で地図を閲覧できる Progressive Web App（PWA）を構築する。

本アプリケーションは、経路検索やナビゲーション機能を目的とせず、以下を主要機能とする。

* 国土地理院地図の表示
* 現在地の表示
* 端末の向いている方向の表示
* 地図タイルのローカル保存
* オフライン環境での地図閲覧
* 表示した地図タイルの自動キャッシュ
* 指定範囲の地図タイルの明示的なオフライン保存
* オンライン時のバックグラウンド更新

PWAを採用することで、App Store / Google Playを経由したリリースを必須とせず、Webアプリケーションとして配布・更新可能な構成とする。

---

# 2. 基本方針

本アプリケーションでは、地図表示について以下の原則を採用する。

1. 地図タイルは可能な限りローカルから表示する
2. ローカルに存在しない場合のみネットワークから取得する
3. ネットワークから取得したタイルはOPFSへ保存する
4. ローカルに存在するタイルは即座に表示する
5. オンラインの場合、ローカル表示後にバックグラウンドで最新版を取得する
6. 更新されたタイルはOPFSへ保存し、次回以降の表示に利用する
7. 明示的にオフライン保存されたタイルは通常キャッシュと区別する
8. 通常キャッシュは容量不足時にアプリ側で削除可能とする
9. 明示保存されたタイルは自動削除対象としない
10. ブラウザーに対してPersistent Storageを要求し、可能な限りデータ消去を防ぐ

この動作は概念的には **Stale-While-Revalidate** に近いものとする。

```text
Tile Request
    │
    ▼
OPFSを確認
    │
    ├── 存在する
    │      │
    │      ├── 即座にMapLibreへ返却
    │      │
    │      └── Onlineの場合
    │             │
    │             ▼
    │        Background Fetch
    │             │
    │             ▼
    │        OPFSを更新
    │
    └── 存在しない
           │
           ├── Online
           │     │
           │     ▼
           │   Fetch
           │     │
           │     ├── MapLibreへ返却
           │     │
           │     └── OPFSへ保存
           │
           └── Offline
                 │
                 ▼
               未取得扱い
```

# 7. MapLibre

地図描画にはMapLibre GL JSを使用する。

Raster Sourceとして地理院タイルを表示する。

MapLibreの `addProtocol()` を利用し、独自タイルプロトコルを実装する。

MapLibreはカスタムURLスキームに対して独自のresource loaderを登録できる。

例：

```text
opfs-gsi://std/{z}/{x}/{y}
```

MapLibreから直接国土地理院URLへアクセスさせず、原則としてTile Repositoryを経由させる。

```text
MapLibre
   │
   ▼
opfs-gsi://
   │
   ▼
MapLibre Protocol Handler
   │
   ▼
TileRepository
   │
   ├── OPFS
   │
   └── GSI HTTP Server
```

これにより、MapLibre自身にキャッシュ戦略を意識させない。

# 8. Tile Repository

地図タイルアクセスの中心となる抽象化を `TileRepository` とする。

```ts
interface TileRepository {
  getTile(request: TileRequest): Promise<TileResult>;

  downloadTile(
    request: TileRequest,
    options?: DownloadOptions,
  ): Promise<TileResult>;

  deleteTile(key: TileKey): Promise<void>;
}
```

MapLibreはこのRepository経由でのみタイルを取得する。

# 10. OPFS

地図タイルのメインストレージにはOrigin Private File Systemを使用する。

OPFSルートは以下で取得する。

```ts
const root = await navigator.storage.getDirectory();
```

OPFSはWebアプリのorigin専用ストレージであり、通常のユーザーファイルシステムから直接参照するものではない。 `navigator.storage.getDirectory()` によりルートDirectoryHandleを取得できる。

---

```text
│       ├── ...
```

# 13. pinned

明示的なオフラインダウンロードによって保存されたタイルには、

```ts
pinned: true
```

を設定する。

通常の地図閲覧によってキャッシュされたタイルは、

```ts
pinned: false
```

とする。

`pinned` はブラウザーAPIのPersistent Storageとは別の、アプリケーション独自の属性である。

ブラウザーの

```ts
navigator.storage.persist()
```

はファイル単位・タイル単位ではなく、そのWebサイトのストレージ全体に対する永続化要求である。ブラウザー側が永続化を認めた場合、ストレージ圧迫を理由とした自動削除を受けにくくなる。要求が必ず許可されるとは限らない。

したがって、

```text
Browser level
    navigator.storage.persist()

Application level
    TileMetadata.pinned
```

の2段階で管理する。

---

# 14. Persistent Storage

アプリ起動時に現在の状態を確認する。

```ts
navigator.storage.persisted()
```

必要に応じて、

```ts
navigator.storage.persist()
```

を要求する。

ただし、ブラウザーによって許可条件が異なるため、

```text
persistent === true
```

を前提にした実装にはしない。

UIにはストレージ状態として、

```text
ストレージ保護
有効 / 未保証
```

程度を表示できるようにする。

# 15. 通常の地図表示

通常表示時のタイル取得フローは以下とする。

## 15.1 ローカルタイルあり + Offline

```text
MapLibre
    ↓
TileRepository
    ↓
OPFS HIT
    ↓
即座に返却
```

ネットワークアクセスは行わない。

---

## 15.2 ローカルタイルなし + Offline

```text
MapLibre
    ↓
TileRepository
    ↓
OPFS MISS
    ↓
Offline
    ↓
Tile unavailable
```

MapLibreにはタイル未取得として返す。

---

## 15.3 ローカルタイルなし + Online

```text
MapLibre
    ↓
TileRepository
    ↓
OPFS MISS
    ↓
Network Fetch
    ↓
MapLibreへ返却
    +
OPFSへ保存
```

取得したタイルは通常キャッシュとして、

```text
pinned = false
```

で保存する。

---

# 16. Stale-While-Revalidate

ローカルタイルが存在する場合は、更新確認よりも表示を優先する。

```text
OPFS HIT
   │
   ├──────────────→ MapLibre
   │                  即座に描画
   │
   └── Online
        │
        ▼
    Revalidation
        │
        ▼
    OPFS update
```

ユーザーはネットワーク待ちをすることなく地図を表示できる。

---

# 17. Background Revalidation

ローカルタイルを表示した後、オンラインであればバックグラウンドで更新確認する。

HTTPサーバーから利用可能な場合、

```text
ETag
Last-Modified
```

を保存し、

```text
If-None-Match
If-Modified-Since
```

を利用する。

サーバーが条件付きリクエストを適切に扱わない場合は、通常GETへフォールバックできるものとする。

結果：

```text
304
    → ファイル更新なし
    → checkedAtのみ更新

200
    → 新しいタイルへ置換

network error
    → 既存タイルを維持
```

---

# 18. Revalidation制御

地図を動かすたびにすべてのタイルへHTTPリクエストすると通信量が増大するため、更新確認間隔を設ける。

例：

```ts
const TILE_REVALIDATE_INTERVAL =
  24 * 60 * 60 * 1000;
```

つまり直近24時間以内に確認済みなら更新確認しない。

値は設定可能な定数とする。

例えば、

```text
24時間
3日
7日
```

などへ変更できる構造とする。

初期値は24時間または数日程度を想定する。

---

# 19. Cache Access

タイルが表示された場合、

```text
lastAccessedAt
```

を更新する。

ただし表示のたびにOPFSメタデータファイルへ同期書き込みするとI/Oが増えるため、メモリ上でbatch化する。

例：

```text
Tile access
Tile access
Tile access
Tile access
     ↓
Memory buffer
     ↓
一定間隔
     ↓
Metadata flush
```

---

# 20. 自動キャッシュ

ユーザーが地図を閲覧しているだけで、表示対象となったオンラインタイルを自動的に保存する。

明示的な操作は不要とする。

```text
ユーザーが東京駅を閲覧
     ↓
MapLibreからタイル要求
     ↓
Network取得
     ↓
表示
     ↓
OPFS保存
```

次回はOPFSから表示する。

これにより、

```text
一度見た場所はオフラインでも見られる
```

というUXを実現する。

ただし通常キャッシュは永続保証対象ではなく、アプリ独自の容量管理により削除される場合がある。

# 23. 明示ダウンロード

ユーザーが保存操作を実行した場合、

1. 指定boundsを取得
2. Zoom範囲を取得
3. 必要なXYZ Tile一覧を算出
4. OPFSに存在するタイルを確認
5. 未取得タイルをダウンロード
6. 既存タイルについて必要に応じて更新
7. すべての対象タイルを `pinned = true` にする

とする。

既に通常キャッシュとして存在するタイルについては、再ダウンロードを必須とせず、

```text
pinned false
    ↓
pinned true
```

へ昇格させることができる。

# 25. Download Queue

大量のタイルを一度に取得しない。

Download Queueを設ける。

```ts
interface TileDownloadJob {
  tile: TileKey;
  priority: number;
  offlineAreaId: string;
}
```

同時HTTP Request数を制限する。

例：

```text
Concurrency = 4〜8
```

初期値：

```text
6
```

とする。

モバイルネットワークや国土地理院サーバーへ過剰な負荷をかけないことを優先する。

---

# 26. Download Resume

明示ダウンロードは途中で停止しても再開可能とする。

OfflineAreaに必要なタイル一覧を保存し、

```text
downloaded
missing
```

を再計算して残りのみ取得する。

アプリ終了中のバックグラウンドダウンロード完遂は保証しない。

PWAがForegroundで動作していることを基本条件とする。

---

# 27. Storage GC

通常キャッシュ：

```ts
pinned === false
```

についてのみ、アプリケーション独自のGarbage Collection対象とする。

---

# 28. GC方式

基本的にはLRU方式を使用する。

削除優先順位：

```text
lastAccessedAt ASC
```

つまり最後に使われてから長時間経過したタイルを先に削除する。

---

# 29. GC対象外

以下は削除しない。

```ts
pinned === true
```

つまり明示ダウンロードしたOfflineAreaのタイルはGC対象外とする。

ユーザーが明示的にOfflineAreaを削除した場合のみ、対象タイルを削除可能とする。

---

# 30. Tile Reference

同一タイルが複数OfflineAreaに含まれる可能性がある。

そのため単純な、

```text
downloadAreaId
```

だけではなく、実装時には多対多関係を考慮する。

概念的には、

```text
Tile
   ↑
   │
OfflineAreaTile
   │
   ↓
OfflineArea
```

とする。

あるOfflineAreaを削除しても、別のOfflineAreaがそのタイルを参照している場合は `pinned` を解除しない。

---

# 31. メタデータ保存

タイル画像はOPFSへ保存する。

構造化メタデータについては、OPFSまたはIndexedDBを利用可能とする。

推奨構成は、

```text
OPFS
    binary tile data

IndexedDB
    tile metadata
    offline areas
    download queue
```

とする。

理由は、

* Binary Fileの保存はOPFSが適する
* 検索・index・transactionはIndexedDBが適する

ためである。

IndexedDBを抽象化する大型ライブラリは原則導入せず、必要最小限のwrapperをアプリ内に実装する。

# 59. concurrency

以下の処理にはConcurrency Limitを設定する。

```text
tile fetch
OPFS write
metadata write
offline download
background revalidation
```

特にMapLibreから同時に多数のタイル要求が来ることを前提とする。

同一Tileに対する同時リクエストはdeduplicateする。

例：

```ts
Map<TileKey, Promise<TileResult>>
```

を利用し、

```text
same tile
same tile
same tile
   ↓
single fetch
```

とする。

# 60. Priority

タイル取得priorityは概ね以下とする。

```text
1. MapLibreが現在表示に必要としているTile
2. 現在画面のBackground Revalidation
3. Explicit Offline Download
4. Background Maintenance
```

ただしOffline Download中でも表示中タイルが遅くならないようにする。

# 82. Atomic Metadata

Tile Binaryの更新とMetadata更新について整合性を考慮する。

原則、

```text
Binary write成功
    ↓
Metadata update
```

とする。

Metadataだけ更新済みでBinaryが存在しない状態は次回アクセス時に修復する。

完全なtransactionは必須とせず、self-healingできる構造を優先する。

# 83. Startup Recovery

ただし全タイル走査は行わない。

```text
metadataあり
binaryなし
```

ならmetadataを削除する。

逆に、

```text
binaryあり
metadataなし
```

の場合はlazyにmetadataを復元可能とする。

# 91. 重要な設計原則

本アプリケーションでは以下を特に重要な原則とする。

```text
1. Local First

2. Offline is normal

3. Render first, update later

4. Explicit download data must not be
   automatically deleted by the application

5. Normal cache may be automatically evicted

6. Do not couple MapLibre directly
   to the network

7. OPFS contains tile binaries

8. Metadata remains searchable

9. Keep dependencies small

10. Browser APIs must always be feature-detected
```

```text
    │         304          200
    │          │            │
    │          │        update OPFS
    │          │            │
    │          └────────────┘
    │
    └──── MISS
            │
            ▼
         online?
        /       \
      NO         YES
      │           │
      ▼           ▼
 unavailable    fetch
                  │

```

```text

        │
        ▼
enumerate tiles
        │
        ▼
local exists?
    /        \
  YES         NO

         │
         ▼

         ▼

```

ブラウザー側には可能であれば、

```ts
await navigator.storage.persist();
```

を要求する。

ただしPersistent Storageはオリジン単位であり、個々のタイルをブラウザーAPI上で個別にpersistent指定することはできない。

そのため、

```text
ブラウザーによるStorage Persistence

+

アプリによるPinned Tile管理
```

を組み合わせることで、オフライン地図を可能な限り長期間保持する設計とする。
